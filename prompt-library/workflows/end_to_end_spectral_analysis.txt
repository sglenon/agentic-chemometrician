# Workflow: Folder-First Spectral Analysis

## Purpose

Drive the chemometrics MCP from a folder of local measurements to a
scientist-reviewed evidence report. Automate the protocol, not the scientist's
final judgment.

## Required sequence

1. Call `create_project` on the source folder.
2. Call `get_project` and surface all unresolved manifest/unit issues.
3. Use `update_project_manifest` only with facts explicitly supplied or
   confirmed by the scientist. Never infer units, roles, targets, or independent
   preparation groups from signal values or filenames.
4. Call `plan_project_analysis` with the objective, task kind, target where
   required, and task-specific analysis options.
5. Present the exact task, candidates, materialized split manifest, blockers,
   claim ceiling, and plan hash.
6. **[HUMAN APPROVAL GATE]** Do not call `approve_project_plan` until the user
   explicitly approves that plan.
7. Call `run_project_analysis` with the returned approval ID.
8. Call `get_project_run` and surface terminal blockers or abstentions.
9. Call `generate_project_report`. Request the optional reproducibility
   notebook only when the scientist asks for it.
10. Return the run-local dashboard, report, figure, and table paths. The
    dashboard renders persisted evidence and must not trigger a second analysis
    or an ad hoc Python script.
11. Present observed evidence, model evidence, tentative explanations,
    unsupported claims, limitations, and the recommended next experiment as
    separate categories.

## Non-negotiable guards

- Invalid or unknown quantitative units block execution.
- Supervised tasks require explicit targets and independent preparation IDs.
- Selected supervised pipelines use the approved materialized group splits.
- Similarity, peak matches, PCA, or model importance never establish chemical
  identity, causality, or purity.
- LOD/LOQ remain not estimable without blanks, low-level standards, independent
  replicates, and a declared method.
- All reported numerical evidence must point to the same run's hash-validated
  local artifact.
- Scientist-facing figures, tables, dashboards, and notebooks are generated
  outputs of the approved run, never an alternate analysis implementation.

## Compatibility

The older `inspect_dataset` → `run_analysis` workflow remains available for
existing clients. Use the folder-first tools above for new work.
